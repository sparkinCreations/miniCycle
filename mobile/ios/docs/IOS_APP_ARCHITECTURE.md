# iOS App Architecture — How the Code Works

How the miniCycle iOS app is put together: what runs where, what happens from tap to
interactive, and what to edit when you want to change something.

> Companions: [`BUILD_AND_RUN.md`](./BUILD_AND_RUN.md) (making builds),
> [`IOS_BUILD_AND_DIFFERENCES.md`](./IOS_BUILD_AND_DIFFERENCES.md) (web-vs-iOS differences),
> [`APP_STORE_RELEASE.md`](./APP_STORE_RELEASE.md) (what's remaining).

## 1. The three layers

The app is a sandwich. From the outside in:

```
┌─────────────────────────────────────────────────────────┐
│ 1. NATIVE SHELL (committed, hand-maintained)            │
│    ios/App/ — Xcode project, Swift AppDelegate,         │
│    icons/splash, Info.plist, signing                    │
│  ┌───────────────────────────────────────────────────┐  │
│  │ 2. CAPACITOR RUNTIME (from npm, via SPM)          │  │
│  │    WKWebView host + the JS↔Swift plugin bridge    │  │
│  │  ┌─────────────────────────────────────────────┐  │  │
│  │  │ 3. WEB PAYLOAD (generated, gitignored)      │  │  │
│  │  │    www/ — the byte-identical miniCycle      │  │  │
│  │  │    web app: modules/, styles/, index.html   │  │  │
│  │  └─────────────────────────────────────────────┘  │  │
│  └───────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

**Layer 3 is the app.** All product logic — tasks, cycles, recurring, themes, stats, undo,
every one of the ~130 ES6 modules — is the web codebase, unchanged. There is no iOS fork of
any module. If you're fixing app behavior, you're editing `web/` and rebuilding the payload.

**Layer 2 is plumbing you never edit.** Capacitor's runtime creates the WKWebView, serves the
payload from the local `capacitor://localhost` origin, and exposes installed native plugins to
JS at runtime.

**Layer 1 is the only iOS-specific code you own.** And it's tiny: the stock Capacitor
`AppDelegate.swift` (unmodified), asset catalogs, Info.plist, project settings. There are
currently **zero lines of custom Swift**.

## 2. Tap → interactive: the boot sequence

1. **Tap.** iOS shows `LaunchScreen.storyboard` — the splash image (blue field + logo) from
   `Assets.xcassets/Splash.imageset`, stretched full-screen. This is instant and static.
2. **Native init.** `AppDelegate` starts Capacitor; Capacitor creates the WKWebView and loads
   `capacitor://localhost/index.html` from the bundled `public/` folder (the synced `www/`).
   The `@capacitor/splash-screen` plugin keeps the splash overlaid on top of the WebView.
3. **Web boot.** Inside the WebView, the normal miniCycle boot runs — `index.html` (the
   transformed `miniCycle.html`) loads `version.js`, then the module entry, then
   `orchestrator → coreBoot → featureBoot → uiBoot`, exactly as on the web. No service
   worker (dropped by the build), no PWA machinery — assets are local files, always "cached".
4. **Splash hide.** `uiBoot.finalizeUI()` calls `initNativeShell()` in
   `capacitorBridge.js`, which (on native only) hides the splash, syncs the status-bar style
   to light/dark mode, and registers the theme observer. The app is interactive.

Total added latency vs the PWA is negligible — the payload loads from disk.

## 3. Directory map — what's committed, what's generated

```
mobile/ios/
├── capacitor.config.json     ✅ committed   appId / appName / webDir / bg color
├── package.json              ✅ committed   Capacitor deps + build scripts
├── CHANGELOG.md              ✅ committed   iOS shell history
├── docs/                     ✅ committed   this documentation
├── node_modules/             ❌ ignored     npm install output
├── www/                      ❌ ignored     GENERATED payload (build-ios-www.cjs)
└── ios/                      ✅ committed   the native project
    └── App/
        ├── App.xcodeproj/            project settings, versions, signing
        ├── App/
        │   ├── AppDelegate.swift     stock Capacitor — no custom code
        │   ├── Assets.xcassets/      AppIcon (1024 opaque) + Splash (3× 2732)
        │   ├── Base.lproj/           LaunchScreen + Main storyboards (stock)
        │   ├── Info.plist            display name, orientations
        │   ├── capacitor.config.json ❌ ignored — derived copy from cap sync
        │   ├── config.xml            ❌ ignored — derived
        │   └── public/               ❌ ignored — cap sync's copy of www/
        └── CapApp-SPM/
            └── Package.swift         SPM manifest listing Capacitor + the 6 plugins
                                      (REGENERATED by cap sync — don't hand-edit)
```

Rule of thumb: **generated things are gitignored; if git tracks it, you own it.**

## 4. The payload build (`www/`)

`web/scripts/build-ios-www.cjs` is a 3-line shim over the shared Android/iOS engine
**`web/scripts/build-capacitor-www.cjs`**. One engine, two output dirs — the web→native
transform is identical per platform and cannot drift. What it does (idempotent, `rmrf` + regen):

1. `miniCycle.html` → `index.html`: drop the PWA-only inline blocks (SW registration,
   boot-failure failsafe, `document.write` version reload), neutralize lite-version redirects,
   drop the manifest link, rewrite `pages/`+`tests/` links to `https://minicycle.app`,
   inject `ios-overrides.css` (hides the automated-test tab).
2. Copy **verbatim**: `version.js`, `miniCycle-main.js`, `modules/`, `styles/`.
3. Prune assets: only files actually referenced by the output (+ `fonts/`) — ~4.6 MB total
   instead of the ~1.2 GB `web/assets/`.
4. Bundle `legal/` (relinked to stay in-app) and the runtime-fetched
   `examples/sample-routines/` + `examples/initial-run/`.

Then `npx cap sync ios` copies `www/` → `ios/App/App/public/` and regenerates
`Package.swift`. Full detail: [`IOS_BUILD_AND_DIFFERENCES.md`](./IOS_BUILD_AND_DIFFERENCES.md).

## 5. Native features: how a JS call reaches Swift

The web app has no bundler, so `@capacitor/*` npm packages can't be `import`ed. Instead all
native access flows through one leaf module that ships inside the payload:

```
web/modules/platform/capacitorBridge.js        (byte-identical on web / Android / iOS)
        │  globalThis.Capacitor?                 ← absent on the web → every export no-ops
        ▼
Capacitor.registerPlugin('LocalNotifications')  ← runtime proxy, guarded by isPluginAvailable
        ▼
Capacitor runtime marshals the call over the WKWebView bridge
        ▼
Swift plugin (from SPM: CapacitorLocalNotifications, …) executes natively
```

The safety contract: on the web there is no `Capacitor` global, so `isNativeApp()` is false
and callers transparently keep their web fallbacks. The bridge is a pure leaf — no DI, not in
`moduleManifests.js`, imported directly like `constants.js`.

Active on iOS:

| Feature | Plugin | Called from |
|---|---|---|
| Splash hide, status-bar light/dark sync | splash-screen, status-bar | `initNativeShell()` ← `uiBoot` |
| Reminder notifications (+ permission prompt) | local-notifications | `features/reminders.js` |
| `.mcyc` export → iOS share sheet ("Save to Files") | filesystem + share | `ui/cycleExportManager.js` |
| Share app / routine text | share | `ui/shareManager.js` |

Inert on iOS (by design, no code change needed): the hardware back-button handler (iOS has no
back button — the listener never fires) and `StatusBar.setBackgroundColor` (Android-only —
optional-chained and `.catch`ed).

**Adding a new native feature:** `npm install @capacitor/<plugin>` in `mobile/ios` (and
`mobile/android`!), `npx cap sync`, add a guarded wrapper in `capacitorBridge.js`, call it
from the web module with the web fallback kept. Never import `@capacitor/*` in a web module.

## 6. Versioning model

| Field | Where | Meaning |
|---|---|---|
| `APP_VERSION` | `web/version.js` | Single source of truth for the app content |
| `MARKETING_VERSION` | `App.xcodeproj/project.pbxproj` (×2: Debug+Release) | The user-visible version — kept equal to `APP_VERSION` |
| `CURRENT_PROJECT_VERSION` | same (×2) | The build number — App Store Connect requires it to strictly increase per upload |

`update-version.sh --ios` maintains all of it: payload rebuild → `MARKETING_VERSION = new`
→ build number +1 → `cap sync`. The bump is **gated on a successful payload build** so the
project can never claim a version while running stale code.

## 7. "I want to change X — what do I edit?"

| Change | Edit | Then |
|---|---|---|
| App behavior / UI / fix a bug | `web/` (normal rules: DI, getLabel, constants) | `npm run sync`, rebuild in Xcode |
| App icon / splash | `ios/App/App/Assets.xcassets` | rebuild |
| Display name, orientation | `ios/App/App/Info.plist` | rebuild |
| App id / name (Capacitor-level) | `capacitor.config.json` | `npx cap sync ios` |
| The web→native transform | `web/scripts/build-capacitor-www.cjs` — **affects Android too**; re-verify both payloads | rebuild both |
| iOS-only CSS tweak | the `ios` entry's `overridesCss` in `build-capacitor-www.cjs` | `npm run sync` |
| Add a native capability | see §5 flow | `cap sync` + rebuild |
| Anything in `www/` or `public/` | **never** — regenerated every build | — |
