# Android App: Build & Differences from the Web App

This document explains how the **Android** app (`mobile/android/`) relates to the web app
(`web/`): how it's packaged, every way it differs, how it's built, and how releases flow.

It is the Android counterpart to [`chrome/BUILD_AND_DIFFERENCES.md`](../chrome/BUILD_AND_DIFFERENCES.md).
If you've read that one, this will feel familiar — the Android web payload is generated by the
**same kind of mechanical, idempotent transform**, just with fewer constraints than MV3.

> **The web payload (`mobile/android/www/`) is generated, not hand-written.** It is produced
> from `web/` by `web/scripts/build-android-www.cjs` and is **gitignored** — never edit it by
> hand; the next build wipes it (`rmrf`) and regenerates it. To change what the app runs,
> change the web app (or the build script) and rebuild.
>
> **The native project (`mobile/android/android/`) IS committed and hand-maintained.** Unlike
> the generated `www/`, the Gradle/Android Studio project holds the app identity, icons,
> splash, permissions, and signing config. Capacitor created it once (`npx cap add android`);
> after that it's yours to customize. `npx cap sync` only copies `www/` into it.

---

## 1. Packaging: Capacitor (not a TWA)

The Android app is a **[Capacitor](https://capacitorjs.com/)** app: a thin native shell whose
single screen is a full-screen WebView that loads the **bundled** web app from a local origin
(`http://localhost`). The web code ships *inside* the APK/AAB — there is no dependency on the
live site, so the app works fully offline out of the box.

We chose Capacitor over a Trusted Web Activity (TWA) because:

- **Offline by default** — assets are bundled, not fetched from `minicycle.app` (a TWA wraps
  the live site and leans on the PWA service worker for offline).
- **Native API access** — Capacitor plugins unlock local notifications (recurring reminders),
  filesystem + share (`.mcyc` import/export), status bar, splash, and hardware back-button
  handling. A TWA's access to these is constrained.
- **No domain coupling** — a TWA requires a Digital Asset Links file hosted on the domain and
  re-verification; Capacitor needs none.

The trade-off is a Gradle project to maintain and a rebuild per release — which is exactly the
same shape as the Chrome `full/` build, so it fits the existing "generate the platform shell
from `web/`" workflow.

---

## 2. Why the Android app differs from the web app at all

The WebView runs the app from a `chrome-extension://`-like **local origin** with files bundled
locally (no server). The build is the set of mechanical transforms that bridge those two worlds —
but there are **fewer** of them than for the Chrome extension:

- **No strict CSP.** `miniCycle.html` has no meta CSP, and Capacitor's WebView enforces none,
  so **inline `<script>` blocks are left inline** — unlike the MV3 build, they are *not*
  externalized to `ext-boot/NN.js`.
- **No page service worker.** The PWA's offline/version-gate/cache machinery is irrelevant
  (assets ship bundled) and a stale SW cache could pin old code, so those PWA-only inline
  blocks are dropped — same as the Chrome build.
- **No PWA manifest.** The `<link rel="manifest">` is dropped; the app identity lives in the
  native project, not a web manifest.
- **Local origin.** Anything not bundled (`pages/`, `tests/`) points at the live site; things
  that should stay in-app (`legal/`) are bundled.

## 3. Web app vs. Android app — complete differences

| Area | Web app (`web/`) | Android app (`mobile/android/`) | Why |
|---|---|---|---|
| **Entry HTML** | `miniCycle.html` | `www/index.html` (renamed) | Capacitor `webDir` convention |
| **Inline scripts** | Allowed via CSP hashes in `netlify.toml` | **Left inline** | WebView enforces no CSP — no externalization needed (unlike MV3) |
| **Boot-failure cache-clear failsafe** | Present (PWA self-heal) | **Dropped** | No SW cache to clear |
| **Version-change `document.write` reload** | Present (PWA cache bust) | **Dropped** | No SW cache versioning |
| **Service-worker registration** (~558 lines) | Present | **Dropped**; the feature-gate block before it is kept | WebView app ships bundled assets |
| **Lite fallback redirect** | 8-second fallback to `lite/` | **Neutralized** (no-op) | `lite/` isn't bundled |
| **PWA manifest** | `manifest.json` + `<link rel="manifest">` | Link **dropped**; identity in native project | App identity is native, not web-manifest |
| **CSP** | `netlify.toml` / `.htaccess` per-inline-script hashes | None (WebView default) | No server; inline scripts kept inline |
| **`legal/` pages** | Linked relatively, served live | **Bundled** into `www/legal/`; back-links rewritten `../miniCycle.html` → `../index.html` | Keep legal nav inside the app |
| **`pages/` + `tests/` links** | Relative | Rewritten to absolute `https://minicycle.app/…` | Not bundled; would 404 from the local origin |
| **Automated-test tab** | Visible in the testing modal | Hidden via `android-overrides.css` | `tests/` isn't bundled; the iframe would 404 |
| **"Check for Updates" button** | Triggers SW update | **No-op** (no SW); updates come via Play Store | Distribution model differs — see §7 |
| **Reminder notifications** | web `Notification` / SW `showNotification` | **Native** via `@capacitor/local-notifications` | WebView lacks the web Notification API — see §9 |
| **Routine export / share** (`.mcyc`) | File System Access / `navigator.share` / download | **Native** share sheet via `@capacitor/share` (+ filesystem) | WebView can't anchor-download or use File System Access — see §9 |
| **Status bar / splash / back button** | n/a (browser chrome) | **Native** via status-bar/splash/app plugins (`initNativeShell()`) | Native shell UX — see §9 |
| **Assets** | Full `web/assets/` (~1.2 GB) | Only **referenced** assets (~0.4 MB) + `fonts/` | Keep the package small |
| **App identity** | PWA title | `appId com.sparkincreations.minicycle`, name "miniCycle" (native) | Play Store identity |
| **External hosts** | `api.web3forms.com` (feedback) | Same (allowed by the WebView; `INTERNET` permission) | Feedback form |
| **Distribution** | Netlify → minicycle.app | Signed AAB → Google Play, or debug APK | — |

**Unchanged / shared verbatim:** `version.js`, `miniCycle-main.js`, the entire `modules/`
tree, the entire `styles/` tree, and the runtime-fetched sample routines
(`examples/sample-routines/`, `examples/initial-run/`). The app ships **byte-identical module
and style code** — only the HTML shell and surrounding plumbing change.

> **Note vs. the Chrome build:** there is **no `manifest.json` dedupe step** here. The Chrome
> Web Store rejects packages with more than one `manifest.json`, so the Chrome build renames
> the sample-routines `manifest.json` → `index.json`. Google Play has no such rule and Capacitor
> doesn't bundle a web `manifest.json`, so the sample-routines `manifest.json` is left as-is.

## 4. The build pipeline

Two layers, mirroring the Chrome flow:

**Layer 1 — generate the web payload.** `web/scripts/build-android-www.cjs` — a thin shim over
the shared Android/iOS engine **`build-capacitor-www.cjs`** (Node stdlib only, no deps; the
transform is identical per platform, only the output dir and overrides stylesheet differ).
Idempotent: it `rmrf`s `mobile/android/www/` and regenerates the whole tree each run,
so the output never drifts from `web/`. Inline-block classification is **content-based** (stable
substrings), not line numbers, so it survives edits to `miniCycle.html`.

Order of operations (`main()`):

1. **`rmrf(OUT)` + recreate** — wipe `www/` and start clean.
2. **`readVersion()`** — parse `APP_VERSION` from `web/version.js` (single source of truth).
3. **`transformHtml()`** — `miniCycle.html` → `www/index.html`:
   - Drop the `<link rel="manifest">`.
   - Rewrite `pages/` + `tests/` links → `https://minicycle.app/…`.
   - Drop the PWA-only inline blocks (boot failsafe, `document.write` reload, SW registration);
     **keep every other inline block inline**.
   - Inject `<link rel="stylesheet" href="android-overrides.css">` before `</head>`.
4. **`copyAppCode()`** — copy `version.js`, `miniCycle-main.js`, `modules/`, `styles/` verbatim.
5. **`copyAssets()`** — copy `fonts/`, then scan output for `assets/…` refs and copy only those.
6. **`copyExamples()`** — copy the runtime-fetched `examples/sample-routines/` + `initial-run/`.
7. **`copyLegal()`** — copy `legal/` and rewrite its back-links to stay in-app.
8. **`pruneJunk()`** — delete `.DS_Store` / `Thumbs.db`.

**Layer 2 — sync into the native project & build.** `npx cap sync android` copies `www/` into
`android/app/src/main/assets/public/` and updates plugins. Then Gradle builds the APK/AAB.

### Running it

```bash
cd mobile/android
npm install                 # first time only — installs Capacitor (@capacitor/{core,cli,android})
npm run sync                # build:www  +  npx cap sync android   (the common loop)
npm run open                # open the project in Android Studio (build/run from there)

# command-line builds (require the Android SDK — see Prerequisites):
npm run assemble:debug      # sync + ./gradlew assembleDebug   → debug APK
npm run assemble:release    # sync + ./gradlew bundleRelease   → release AAB (then sign)
```

The web payload alone can also be regenerated from `web/`:

```bash
cd web && npm run build:android        # web/ → mobile/android/www/  (then cap sync)
```

### Prerequisites

- **Node + JDK 17+** — for Capacitor and Gradle.
- **Android SDK** (via Android Studio) with `ANDROID_HOME`/`local.properties` set — required to
  compile the APK/AAB. The web payload build and `npx cap sync` work **without** the SDK; only
  the Gradle compile needs it. The simplest path is to run `npm run open` and build from
  Android Studio, which manages the SDK for you.

## 5. The native project (`mobile/android/android/`)

Generated once by `npx cap add android`; committed and customized thereafter.

- **App identity:** `applicationId` / `namespace` = `com.sparkincreations.minicycle`, app name
  "miniCycle" (`res/values/strings.xml`). Set in `android/app/build.gradle`.
- **Permissions:** `INTERNET` (feedback form → `api.web3forms.com`) plus `POST_NOTIFICATIONS`
  (+ `RECEIVE_BOOT_COMPLETED`, `WAKE_LOCK`), merged automatically from the
  `@capacitor/local-notifications` plugin's manifest — they are not declared by hand.
  Filesystem/Share need no extra permission (cache dir + system share sheet).
- **Version:** `versionName` in `android/app/build.gradle` tracks `APP_VERSION`; `versionCode`
  is a separate integer that must increase for every Play upload (see §7).
- **Config:** `mobile/android/capacitor.config.json` (`appId`, `appName`, `webDir: "www"`,
  background color). `cap sync` copies a derived `capacitor.config.json` into the app assets.

**Do not hand-edit `www/`** — it's regenerated. Native customizations (icons, splash, manifest,
signing) go in `android/`.


## 7. How updates & releases work

- **Single version source.** `web/version.js` (`APP_VERSION`) drives the web app, the SW
  `CACHE_VERSION`, the Chrome extension's manifest, *and* the Android `versionName`. Keep
  `versionName` in `android/app/build.gradle` in sync with it on each release.
- **`versionCode`** is Android-specific: it is **not** a semver string but a monotonically
  increasing integer. Google Play rejects an upload whose `versionCode` is not greater than the
  last. Bump it by 1 every release (independent of `versionName`).
- **Version bump from the release script:** `update-version.sh --android` regenerates the web
  payload, syncs `versionName` to `APP_VERSION`, and **bumps `versionCode` by 1** in
  `build.gradle` (then `cap sync` if Capacitor is installed) — the Android counterpart to
  `--chrome`. It runs before the git-tag stage so the bump is part of the release:

  ```bash
  cd web && ./scripts/update-version.sh --auto --android        # bump + rebuild Android payload
  cd web && ./scripts/update-version.sh --auto --android --chrome --tag   # both platforms + tag
  ```

- **Release build:** `npm run sync`, then build a **signed AAB** (`./gradlew bundleRelease` or
  Android Studio → Build → Generate Signed Bundle) and upload to the Play Console. Use a debug
  APK (`npm run assemble:debug`) for sideload testing.
- **No CSP hash step** (web app) and **no zip step** (Chrome) here — Android distributes a
  signed bundle through Play.
- **Keystore:** keep the upload keystore **out of the repo** (the generated `android/.gitignore`
  has commented-out `*.jks`/`*.keystore` rules — uncomment them if you place a keystore in the
  project, or store it elsewhere entirely).

## 8. Maintenance rules

- **Never hand-edit `mobile/android/www/`** — it's regenerated. Edit `web/` or the build script.
- **Don't commit `www/`, `node_modules/`, or the copied `app/src/main/assets/public/`** — all
  gitignored.
- **Keep `versionName` in sync with `APP_VERSION`** and **bump `versionCode`** every release.
- **After restructuring `miniCycle.html` inline scripts,** re-verify the `RULES` table in
  `build-capacitor-www.cjs` (the shared Android/iOS engine; it shares the substring matchers
  with the Chrome build — update both).
- **Re-run `npx cap sync`** after every web payload rebuild and after adding any Capacitor plugin.

## 9. Native feature bridges

The web app has no bundler (it loads ES modules directly), so the `@capacitor/*` JS packages
**cannot be `import`ed** in the browser. Instead, all native access goes through a single leaf
module, **`web/modules/platform/capacitorBridge.js`**, which reaches plugins via the runtime
proxy (`Capacitor.registerPlugin(name)`) — guarded by `Capacitor.isPluginAvailable(name)`.

**The safety contract:** on the web there is no global `Capacitor`, so `isNativeApp()` is false
and every bridge export is a no-op returning a "not handled" result. Callers keep their existing
web behavior unchanged and only gain native behavior inside the Android app. The bridge is a
pure leaf (no DI, imports nothing from other modules) — imported directly like `constants.js`,
**not** registered in `moduleManifests.js`.

The native side is wired by `npm install @capacitor/<plugin>` + `npx cap sync` in
`mobile/android` (the plugins are committed in `package.json`); `cap sync` registers them in the
Gradle project, and `LocalNotifications` merges the `POST_NOTIFICATIONS` permission automatically
via Android manifest merging.

Implemented bridges and where they hook in:

| Bridge | Plugin(s) | Web-app integration point | Web fallback (unchanged) |
|---|---|---|---|
| **Status bar / Splash / Back button** | `@capacitor/status-bar`, `@capacitor/splash-screen`, `@capacitor/app` | `initNativeShell()` called from `uiBoot.js` | n/a (native-only) |
| **Local notifications** | `@capacitor/local-notifications` | `modules/features/reminders.js` — native send path + permission flow | web `Notification` / SW `showNotification` |
| **Routine export** (`.mcyc`) | `@capacitor/filesystem`, `@capacitor/share` | `modules/ui/cycleExportManager.js` | File System Access API → anchor download |
| **Routine / app share** | `@capacitor/share` (+ filesystem for files) | `modules/ui/shareManager.js` | `navigator.share` → download / clipboard |

- **Status bar** tracks the app's `dark-mode` class via a `MutationObserver`, so it re-themes
  when the user toggles dark mode.
- **Back button** dispatches `Escape` to close the top-most open modal/menu; only navigates
  back / exits when nothing is open.
- **Export/share** write the `.mcyc` to the cache dir then open the Android share sheet (which
  includes "Save to Files"), since the WebView can't do an anchor download or the File System
  Access API.

Still open (not yet wired):

- **`.mcyc` import** — the file-open path (deep links / `chrome.intent` for `.mcyc` files) is
  not yet handled; import still uses the web file picker.
- **Notification small icon** — currently the launcher icon; add a monochrome
  `res/drawable/ic_stat_*` and set `smallIcon` in the bridge to brand the status-bar icon.
- **"Check for Updates"** — a no-op in the app (updates ship via Play); hide it or repoint it to
  the Play listing.
