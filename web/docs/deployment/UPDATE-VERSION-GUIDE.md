## Version.js Overview

### 🆕 What is version.js? (Added in v1.330)

**version.js** is the **single source of truth** for the app version across all contexts (browser window, service worker, and all modules).

**The Problem It Solves:**
Before v1.330, modules were being cached **twice** with different URLs:
- HTML: `notifications.js?v=1.329` (versioned)
- Dynamic imports: `notifications.js` (un-versioned)

This created duplicate cache entries, and users were stuck on old versions because:
- Service worker cached both URLs
- Un-versioned imports served old cached files
- Version increments only affected one URL, not both

**The Solution:**
```javascript
// version.js - Auto-generated by update-version.sh
globalThis.APP_VERSION = '1.330';
globalThis.CACHE_VERSION = 101;
```

### How It Works

**1. Loaded First (Before Any Scripts)**
```html
<!-- miniCycle.html - Line ~80 -->
<script src="./version.js"></script>
<!-- In the browser, window.APP_VERSION aliases globalThis.APP_VERSION -->
```

**2. Service Worker Uses Inlined Version**
```javascript
// service-worker.js - updated by update-version.sh
var APP_VERSION = '1.330';
var CACHE_VERSION = 'v104';
```

**3. All Dynamic Imports Use It**
```javascript
// modules/boot/orchestrator.js
const APP_VERSION = globalThis.APP_VERSION || 'dev-local';
const withV = (path) => `${path}?v=${APP_VERSION}`;

// Every module gets versioned
await import(withV('./modules/notifications.js'));
// Loads: notifications.js?v=1.330
```

### Why This Matters

**Before (v1.329):**
```javascript
// HTML loaded:
<script src="notifications.js?v=1.329"></script>

// Dynamic import:
await import('./modules/notifications.js');  // Un-versioned!

// Result: TWO cache entries
// - notifications.js (old, never refreshes)
// - notifications.js?v=1.329 (new, HTML only)
```

**After (v1.330):**
```javascript
// HTML loads version.js first
globalThis.APP_VERSION = '1.330';

// Dynamic import uses same version
await import(`./modules/notifications.js?v=${globalThis.APP_VERSION}`);

// Result: ONE cache entry
// - notifications.js?v=1.330 (everyone uses this)
// Version increment forces everyone to fetch fresh copy
```

### Update Workflow

**When you run `./scripts/update-version.sh`:**

1. **Generates version.js first** (new version number)
2. Updates all selected files to reference the new version
3. Creates backup in `backup/version_update_[timestamp]/`
4. Validates all changes

**Example update:**
```bash
./scripts/update-version.sh
# Enter new version: 1.331

# Script generates:
# version.js → globalThis.APP_VERSION = '1.331'
# miniCycle.html → loads version.js
# service-worker.js → APP_VERSION/CACHE_VERSION inlined
# All modules → imported with ?v=1.331
```

### appInit Singleton Consistency

**All appInit imports must use the same version suffix:**
```javascript
const APP_VERSION = globalThis.APP_VERSION || 'dev-local';
const { appInit } = await import(`./modules/core/appInit.js?v=${APP_VERSION}`);
```

**Why:** versioned and unversioned imports are different module instances. Keeping a single version suffix preserves singleton behavior.

## DI-Pure Module Versioning

### What Changed in v4.0

**Before v4.0:** The script updated 40+ module files with hardcoded version numbers (`@version` JSDoc tags, `this.version = 'X.XXX'`).

**After v4.0:** Modules receive their version via dependency injection. The script only updates ~10 core files.

### How It Works

```
version.js (this script generates it)
    ↓
globalThis.APP_VERSION (set by version.js)
    ↓
modules/boot/coreBoot.js builds: deps.core.AppMeta = { version: APP_VERSION }
    ↓
initModule({ AppMeta: deps.core.AppMeta, ... })
    ↓
this.version = mergedDeps.AppMeta?.version
    ↓
const version = this.version || 'dev-local'
    ↓
import(`./submodule.js?v=${version}`)
```

### Benefits

- **No hardcoded versions** in 40+ module files
- **Single source of truth** (version.js)
- **Modules are DI-pure** (no window.* version access)
- **Cache-busting** via dynamic imports works automatically
- **Faster updates** - fewer files to modify

### Legacy Reference

The v3.0 script with module auto-discovery is archived at:
`archive/update-version-v3-autodiscovery.sh`

## What It Does

The `scripts/update-version.sh` script automates version number updates across **core miniCycle files** while maintaining backups and validating changes. It prevents manual version sync errors and ensures PWA cache invalidation.

**Key Features:**
- **Auto-generates version.js** as single source of truth
- Updates version numbers in ~10 core files (v4.0 - modules use DI)
- Creates timestamped backups with auto-restore scripts
- Validates changes after updating
- Supports 3 update modes (all, selective, custom)
- macOS and Linux compatible
- Maintains only last 3 backups automatically

**Version Types:**
1. **App Version** (e.g., `1.392`) - User-facing version in version.js, HTML meta tags, manifests, and JS
2. **Service Worker Cache Version** (e.g., `v212`) - Forces PWA cache invalidation

**Files Updated (v5.x):**
- **version.js** - Single source of truth (auto-generated)
- **miniCycle.html** - ?v= params, currentVersion, meta tags
- **styles/main.css** - @import version parameters
- **service-worker.js** - CACHE_VERSION + APP_VERSION
- **pages/product.html**
- **manifest.json**
- **package.json**
- **docs/PROJECT_STATS.md**
- **Lite files (with `--lite` or `--lite-only`):**
  - **lite/miniCycle-lite.html**
  - **lite/miniCycle-lite-scripts.js**
  - **lite/miniCycle-lite-styles.css**
  - **manifest-lite.json**

> **Note:** Module files (modules/*.js) are NO LONGER updated by this script. They receive version via DI.

## macOS-Specific Intricacies

### Critical: sed -i Syntax Difference

**The Problem:**
- **macOS (BSD sed)**: Requires `sed -i ""` (empty string after -i)
- **Linux (GNU sed)**: Uses `sed -i` (no argument after -i)

**How the script handles it:**
```bash
# Lines 98-102 in scripts/update-version.sh
if [[ "$OSTYPE" == "darwin"* ]]; then
  SED_INPLACE=(sed -i "")    # macOS: empty string after -i
else
  SED_INPLACE=(sed -i)       # Linux: no argument
fi

# Later usage (line 343):
"${SED_INPLACE[@]}" "s/?v=[0-9.]*/?v=$NEW_VERSION/g" miniCycle.html
```

**Why this matters:**
Without the empty string on macOS, you'd get this error:
```bash
sed: 1: "miniCycle.html": invalid command code m
```

**Manual sed commands on macOS:**
```bash
# ❌ WRONG (Linux syntax on macOS)
sed -i 's/1.320/1.321/g' miniCycle.html

# ✅ CORRECT (macOS requires empty string)
sed -i "" 's/1.320/1.321/g' miniCycle.html
```

---

### macOS Bash Version (3.2.57)

**The Problem:**
macOS ships with Bash 3.2.57 (from 2007!) due to GPLv3 licensing. Newer Bash 4+ features aren't available.

**What the script avoids:**
```bash
# ❌ Bash 4+ associative arrays (NOT used in script)
declare -A FILES_TO_UPDATE
FILES_TO_UPDATE["miniCycle.html"]="yes"

# ✅ Bash 3 compatible string tracking (used in script)
FILES_TO_UPDATE="|miniCycle.html|service-worker.js|"

# Check if file is in list (line 320):
should_update() {
    local file=$1
    [[ "$FILES_TO_UPDATE" == *"|$file|"* ]]
}
```

**Checking your Bash version:**
```bash
bash --version
# GNU bash, version 3.2.57(1)-release (arm64-apple-darwin24)
```

### macOS find Command Differences

**Backup cleanup (lines 68-77):**
```bash
# Works on both macOS and Linux
find "$BACKUP_DIR" -maxdepth 1 -type d -name "version_update_*" | wc -l | tr -d ' '
```

**Why `tr -d ' '` is needed on macOS:**
```bash

# tr -d ' ' removes spaces for consistent parsing

#!/bin/bash

# Get current version
CURRENT=$(grep -oE 'content="[0-9.]*"' miniCycle.html | head -1 | grep -oE '[0-9.]+')

# Parse major.minor
MAJOR=$(echo $CURRENT | cut -d. -f1)
MINOR=$(echo $CURRENT | cut -d. -f2)

# Increment minor version
NEW_MINOR=$((MINOR + 1))
NEW_VERSION="$MAJOR.$NEW_MINOR"

# Get current SW version and increment
CURRENT_SW=$(grep -oE "CACHE_VERSION = 'v[0-9]+'" service-worker.js | grep -oE '[0-9]+')
NEW_SW="v$((CURRENT_SW + 1))"

echo "Auto-incrementing version:"
echo "  $CURRENT → $NEW_VERSION"
echo "  v$CURRENT_SW → $NEW_SW"

# Run scripts/update-version.sh with auto-confirm (requires modification)
./scripts/update-version.sh
```

**Pre-commit hook to verify versions are synchronized:**

**.git/hooks/pre-commit:**
```bash
#!/bin/bash

# Extract versions from different files
HTML_VERSION=$(grep -oE 'app-version" content="[0-9.]*"' miniCycle.html | grep -oE '[0-9.]+')
JS_VERSION=$(grep -oE "APP_VERSION = '[0-9.]+'" version.js | grep -oE '[0-9.]+')
MANIFEST_VERSION=$(grep -oE '"version": "[0-9.]*"' manifest.json | grep -oE '[0-9.]+')

# Check if they match
if [ "$HTML_VERSION" != "$JS_VERSION" ] || [ "$HTML_VERSION" != "$MANIFEST_VERSION" ]; then
    echo "❌ ERROR: Version mismatch detected!"
    echo "   HTML: $HTML_VERSION"
    echo "   JS: $JS_VERSION"
    echo "   Manifest: $MANIFEST_VERSION"
    echo ""
    echo "Run ./scripts/update-version.sh to synchronize versions"
    exit 1
fi

echo "✅ Version check passed: $HTML_VERSION"
```

### Creating Version Update Reports

**Generate a diff report after updating:**

```bash
#!/bin/bash
# version-diff-report.sh

BACKUP_FOLDER="backup/version_update_$(date +%Y%m%d)_*"
LATEST_BACKUP=$(ls -td backup/version_update_* | head -1)

echo "Version Update Diff Report"
echo "=========================="
echo "Backup: $LATEST_BACKUP"
echo ""

for file in miniCycle.html service-worker.js manifest.json version.js; do
    echo "--- $file ---"
    diff -u "$LATEST_BACKUP/$file" "$file" | grep -E '^\+|^-' | grep -v '+++\|---'
    echo ""
done
```
