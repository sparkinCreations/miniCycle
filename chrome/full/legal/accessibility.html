♿ Accessibility Statement for miniCycle

Last Updated: October 13, 2026

Version: 3.0

Our Commitment

sparkinCreations is committed to making miniCycle accessible to everyone, including people with disabilities. We design and test miniCycle with the goal of meeting WCAG 2.2 Level AA and continuously improve the accessibility of our application.

Accessibility Features

miniCycle includes the following accessibility features, available in Settings > Accessibility:

  • Reduced Motion — Stops animations and transitions for users sensitive to motion, whether switched on here or in your operating system
  • High Contrast — Increases border visibility, text contrast, and element distinction in both light and dark modes
  • Font Size Control — Four size presets (Small, Default, Large, Extra Large) for comfortable reading
  • Show Move Arrows — Provides button-based task reordering as an alternative to drag-and-drop
  • Show Three Dots Menu — Exposes task options via a visible menu button instead of requiring gestures
  • Dark Mode — Reduces eye strain in low-light environments, with a CSS fallback that respects your system's dark mode preference before JavaScript loads
  • Guided Tour — Optional interactive walkthrough that highlights key UI elements, with keyboard navigation and focus trapping

Technical Accessibility

  • Semantic HTML — Native <dialog> elements for modals with automatic focus management, trapping, and restoration
  • ARIA Labels — 68+ interactive elements include descriptive labels for screen readers, with aria-live regions for dynamic content updates (notifications, task list filtering)
  • Keyboard Navigation — All core features are accessible via keyboard, including roving tabindex patterns for lists, toolbars, and grids (arrow keys, Home/End, Enter/Space)
  • Skip Navigation — Skip-to-content link allows keyboard users to bypass the header and jump directly to the main content
  • Focus Indicators — Visible :focus-visible outlines throughout, with enhanced 3px outlines in high contrast mode
  • Respects System Preferences — Honors prefers-reduced-motion and prefers-color-scheme (CSS dark mode fallback before JavaScript loads)
  • No Flash Prevention — Accessibility settings load before CSS renders to prevent animation or contrast flash on page load
  • Color Contrast — Text on solid backgrounds is checked against WCAG AA ratios (4.5:1 for normal text, 3:1 for large text) on every release, across the built-in themes, and text over the page gradient is measured at every gradient stop. Disabled states use visual cues beyond color alone

How We Test

Each release is checked in a real browser as part of our automated test suite: keyboard operation and focus behavior (including where focus lands when dialogs and views close), color contrast on solid backgrounds and over the page gradient, reduced motion, responsive layouts at seven screen sizes, and accessible names and roles for custom controls. The contrast check uses axe-core's color-contrast rule plus hand-measured checks for what axe cannot judge, and runs as its own job in continuous integration so it cannot be skipped by an unrelated failure.

Independent accessibility audits in October 2026 found defects in focus handling, dialog naming, color contrast and reduced motion. Each has been fixed and each fix is covered by a test that replays the audit's reproduction steps.

Known Limitations

We are aware of the following areas where accessibility can be improved or has not yet been verified:

  • By design: the outline of an incomplete task's checkbox is lighter than WCAG recommends for a control boundary (about 1.5:1 against the task). The whole task row is the activation target and the completed state adds a filled checkmark, but the empty ring itself is faint. High Contrast mode gives it a stronger outline.
  • Drag-and-drop task reordering requires the "Show Move Arrows" setting for keyboard and switch users — this alternative is always available via Settings
  • Custom vocabulary theme and personalization color combinations may not meet WCAG contrast ratios in all configurations — use High Contrast mode for guaranteed visibility
  • Screen reader testing with VoiceOver, NVDA, JAWS and TalkBack has not yet been formally performed and documented
  • Browser zoom at 200% and 400% has not yet been formally verified; the built-in font size settings are tested

Because testing across every browser, assistive technology, feature state and custom color combination is ongoing, this statement should not be read as a formal claim of complete WCAG 2.2 Level AA conformance.
